# Commissary address and map access (after 0.10.9)

Player report (Workshop comment, 26 October 2026): a player rented a space at Industry City Commissary and had stock delivered there, but could not find the commissary. Its phone contact showed no address, and the player could not find it on the map. The version stays 0.10.9; this change is for the next build.

## Cause

Commissary contacts are created without an address: `Commissary.Unlock` passes none to `Contact.GetContact`, and `Commissary.ContactFor` uses `Contact.EnsurePermanentContact`. For a contact without an address, the game's `ContactsApp.SetUpHeader` hides the address line and View on map. The call still works through `callDialogTypeOverride`. The welcome, rental and call texts named the commissary but not its street. BizMan's rented-space panel showed the name, rent and start day, but no address or GPS. This affected all five commissaries, Lower Manhattan as well as Industry City. The map filter (Street food > Commissaries) already includes every commissary's building. It was not changed.

## Change

Display only. Nothing new is saved, and the save schema is unchanged.

- **Phone contact** (`ModContacts.HeaderPostfix`, registered in `Patches.cs` on `ContactsApp.SetUpHeader(Contact)` with the standard helper, which logs `Active` or `Not active`). This postfix handles only contacts named `foodtrucks-commissary-<id>` whose ID is still in `data/commissaries.json`. It does nothing after the uninstall step. After the game builds the header, it shows the host building's address in the game's own format (`EventLocations.ReadableAddress`, through `World.BuildingAt`) and a View on map button. The button closes the phone and opens the city map on the building, with its card selected. It uses the same steps as the game's View on map: `CityMap.buildingToFocus` and `Toggle`, or `CityMap.FocusOnBuilding` when the map is already open. The address is resolved each time the header opens. Contacts and spaces from older saves therefore show it without a new visit. While the address cannot be resolved, the header says "Address unavailable" and shows no map button. The listener the postfix adds is removed before the next contact's header is built. The contact's own address fields are left unset: the game's address branch would tie the call button to the host tenant's opening hours. The call button is the game's, unchanged.
- **BizMan, Commissary space** (`BizManVehiclePage.CommissarySpace`): an Address row, the line "Set destination leads to the building; the loading bay is beside it." and a Set destination button, which uses the game's Destination guider through `EventLocations.SetDestination`. It targets the building entrance, not the bay stall. While the address cannot be resolved, the row shows "Address unavailable" and the button is disabled.
- **Texts** (`Commissary.Unlock`, `Commissary.ApplySpace`, `CommissaryDialog.Start`): when the address resolves, the welcome, rent and move texts and the call's opening line use new keys that include `{address}`. These are `foodtrucks:message_commissary_welcome_phone_address`, `..._space_rented_address`, `..._space_moved_address`, `foodtrucks:dialog_commissary_start_spaces_address` and `..._start_standing_address`. Otherwise they use the old keys. Old saved messages keep their keys and data, so they still display as before. A released space's text is unchanged.
- Shared accessor: `unity/FoodTrucks/Scripts/CommissaryLocation.cs`.

Not changed: `data/commissaries.json`, discovery and unlock rules, Core state and ledger, the logistics `ba:street_parking` sentinel, map filters and search (no named map aliases), and host business names and registrations.

Game members were checked with ILSpy against the cached `BigAmbitions.dll` (SHA-256 `9427561B81AAAB2ADA09C22A3C98DD9A4017A65225B389513885BF336852E911`): `private void SetUpHeader(Contact contact)`; the private fields `Button viewOnMapButton`, `GameObject addressGameObject` and `TextLocalizationComponent addressLabel`; the address-undefined branch, which hides the address and map button and keeps the call when `callDialogTypeOverride` is set; `ViewOnMapButtonOnClick`, which closes the full menu and sets `cityMap.buildingToFocus` before `Toggle`; and `CityMap.FocusOnBuilding(CityBuildingController)`, `buildingToFocus` and `IsOpen`. `TextLocalizationComponent.SetValue(string text, bool clearKey = false)` is in `HGPlugins.dll`.

## Evidence

- **Checked (automated):** `tools/tests/test_commissary_address.py` compiles the production `CommissaryLocation.cs` and `EventLocations.cs`, the registered header postfix and `BizManVehiclePage.CommissarySpace` against stand-ins. The stand-ins follow the game's header branches, map focus, guider and street names (`tools/tests/commissary_address/Scenarios.cs`), and the harness binds postfix parameters by name, as Harmony does. Cases: an Industry City contact from an older save with a rented space; all five shipped sites, Lower Manhattan included; View on map with the map closed and open; switching between commissary, addressless and business contacts; other contacts untouched; an unresolved building or street name, then resolved on the next open; the uninstall step; the call button usable throughout; BizMan's address, bay line and Set destination; the new message keys; and old payloads. Static checks cover the registration, the handler parameter names, the new locale keys and their placeholders. When `BA_GAME_DLLS` and `ilspycmd` are available, an optional test reads the game members again. This test failed on the pre-fix tree (`d2e2b3e`) and passes with this change.
- **Pending (in game):** the checks in `CHECKS.md` (CA1 to CA5). The patch has not been compiled against the full game and Unity references or run in the game.
