# Event addresses, 0.10.8

City event locations are curated building address IDs in `data/pitches.json`, resolved to native entrance positions by `World`. The offer, reminder, booking confirmation, phone and arrival notices previously displayed separate labels without building numbers. Those labels use written street names instead of the native map spelling. No arbitrary event coordinates are generated.

Catering offers are selected from native building entrances, including park-adjacent buildings. `Catering.PlaceName` previously split the internal `street#number` ID and sent the street ID through Localizor. Street IDs are not locale keys: the game reads `StreetData.streetLocalization` through `Streets.AddressHelper`. This could expose raw IDs even though the underlying building exists. The player's exact screenshot/save was not supplied, so this is a confirmed code defect and likely explanation, not a reproduction of their particular save.

`EventLocations` resolves the exact building and calls its native address formatter, shared with the game map. Missing or unresolved street data is rejected before offering/booking. City-event notices and phone text share that resolver. Catering descriptions share it too, covering offers, confirmations, missed and paid notices. A missing location displays a readable unavailable label instead of an ID. Stored phone messages for live offers/bookings are corrected when day, start time and kind identify a unique location; ambiguous/historical messages are left intact.

City-event phone entries retain fully booked events and offer Set destination through the native address guider. Both event families explain their existing map highlight: Street food > Premium spots and events, or Catering bookings. The native map search indexes only buildings with business names, so an address existing in the game does not guarantee a search dropdown result; the highlight and city-event GPS avoid relying on that search.

Invalid city events are cancelled before expiry, refunding bookings for future events and unclaimed bookings still retained from an ended event. Invalid unstarted catering bookings are removed before no-show judgement without changing reputation, failure counts, money or stock. Started catering retains its settlement. This does not reverse past penalties already archived in old saves; those do not retain proof that the address caused the miss. Save schema remains 2; no new persistent fields or binary dependencies.
